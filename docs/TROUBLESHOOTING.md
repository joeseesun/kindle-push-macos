# 常见问题

## 应用打开后提示缺少组件

Python 和 Pandoc 都在应用里。出现这个提示说明应用不完整，请重新下载并安装。自己从源码构建时，运行 `./script/fetch_runtime.sh`，或 `brew install python pandoc`。

## USB 只有充电，没有磁盘

先从 KOReader 退出到 Kindle 原生界面，再拔插。仍只有充电时换支持数据传输的线和 USB 端口。只有看到 Finder 中的 Kindle 磁盘，才执行 USB 安装脚本。

## 自动寻找失败

- 确认 Mac 和 Kindle 连接同一个 Wi-Fi，Kindle 没有休眠。
- 确认 KOReader 的 SSH 服务器已启动，端口为 2222。
- 点击「自动寻找」，或在「手动连接」中输入 Kindle 的 IPv4。
- 检查访客网络是否隔离客户端；不要为了本工具开放路由器端口转发。
- macOS 如果询问局域网权限，需要允许应用访问局域网才能工作。
- 大于 /24 的网络仅扫描 Mac 附近的 /24 和已观察到的 ARP 邻居，其他地址请手动输入。

## 提示设备身份不一致

先检查 IP。它可能已分配给另一台设备。只有在你确认 Kindle 更换或主机密钥重新生成后，才按首次配置文档重新配对。

## Markdown 转换失败

检查图片是否实际下载到本机、路径是否正确、知识库是否存在重名附件；iCloud 的占位文件需先下载。嵌入笔记先查看是否有循环。

终端可查看更完整的信息：

```sh
python3 wifi-push/kindle_push.py --convert-only '/完整路径/文章.md'
```

不要把包含个人文章内容、密钥或完整设备配置的日志直接贴进公开 Issue。

## 已发送但 Kindle 首页没有显示

新文件在 KOReader 文件浏览器的 `/mnt/us/documents/我的文章`。重新进入文件夹刷新。乔木首页的最近阅读列表可能要打开文章一次后才出现。

## macOS 提示开发者无法验证

当前发布包没有 Apple Developer ID 公证，使用本地 ad-hoc 签名。确认来源为本仓库并核对 SHA-256 后，可自行选择系统允许的单应用打开方式，或从源码构建；不需要全局关闭系统安全检查。

## 中途退出、重发、阅读批注

关闭应用时正在运行的传输进程可能短暂继续，重开后可以重试。接收端先写临时文件，长度正确后再替换正文；成功后 Mac 还会读回做哈希校验。网络中断不会把半个 EPUB 当成成功。

重发同一原文件会更新同一个远端文件名。内容改动可能影响原阅读位置和批注；需要保留旧版请先另存原文。
