# 连接与数据说明

## 数据放在哪里

| 数据 | 位置 |
| --- | --- |
| 专用客户端私钥 | `~/Library/Application Support/KindlePush/id_ed25519` |
| 已配对的设备身份 | 同目录 `known_hosts` |
| 上一次 Kindle IP | 同目录 `config.json` |
| 首次配置备份 | 同目录 `backups/` |
| 文章列表和发送结果 | 应用 UserDefaults，仅本机 |
| 转换后的文章副本 | `~/Documents/Kindle推送/已转换/` |
| Kindle 文章 | `/mnt/us/documents/我的文章/` |
| Kindle 接收脚本与公钥 | `/mnt/us/koreader/settings/SSH/` |
| 翻译 API Key | macOS 钥匙串；已有 Magpie 配置仅复用引用 |
| 翻译设置（不含密钥） | `~/Library/Application Support/KindlePush/translation.json` |
| 翻译副本、日志和检查点 | 同目录 `translations/`（包含正文，不应分享） |
| 隔离翻译环境 | 同目录 `translation-runtime/` |

源文章不改动，不建立自动同步任务，不绑定任何云账号。不把任何个人密钥、配置、文章作为发布包的一部分。

主动点击试译或翻译时，书籍正文会提交至翻译设置里的模型服务，受该服务的数据政策与 API 计费约束。仅直接发送时不经过模型服务。密钥只在进程内读取并通过环境提供给翻译引擎，不放入命令参数或日志。更换服务地址不会继承原服务密钥。

## 设备认证

首次 USB 写入受限公钥，随后在可信网络进行明确的首次信任配对。之后所有连接要求同一个 ED25519 主机密钥；自动发现只探测 TCP 2222，并在发起认证前核对主机密钥。SSH 客户端再次执行严格主机校验。

设备接收脚本以 Kindle 的 root 身份运行，因为这是 KOReader 的设备环境，但该专用密钥被 forced-command 限定为 `ping`、`put`、`get`，不能执行任意 shell 命令或转发端口。接收端仅允许目标文件夹内的 `.epub` 名称、拒绝路径分隔符，限制每个上传文件 100 MB。

这不是一个针对所有潜在恶意本地用户或恶意电子书的沙箱。请只转换自己信任的文章；Pandoc/图片解析器会读取选择文章所引用的本地资源，远程图片会触发下载。保护好本机私钥；不要将 SSH 端口暴露到公网。

## 停用与撤销

先退出应用，在 KOReader 的 SSH 服务器菜单停止服务并取消自动启动。需要彻底撤销时，通过 USB 从 `authorized_keys` 删除本应用那一行受限公钥。其他用户密钥不要删除。

可用安装时的备份恢复修改前的设置与公钥文件，但若之后已有其他改动，应逐项合并而不是整份覆盖。移除 Mac 应用不会自动删除文章或密钥；需要清理时先做好自己的备份。
